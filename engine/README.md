# Engine

The engine turns an `AnalysisQuestion` into SPARQL, runs it against the
SAWGraph endpoints, and turns the rows into map features. It is headless: no
React, no Leaflet, no DOM. The same code runs in the browser (`ui/`) and in
Node (`scripts/`).

`tests/headless.test.ts` keeps it that way. It fails if any file here imports a
package or anything outside `engine/`, or touches `window`, `document`,
`localStorage`, `sessionStorage`, `navigator` or `import.meta.env`. The tests
in `tests/` are held to the same import rule, with only `vitest` and Node
builtins added, so a UI test that lands here by mistake fails. The UI may
import the engine; the engine never imports the UI.

## Entry points

| What | Where |
|---|---|
| Question to pipeline steps | `planPipeline(question)` in `planner.ts` |
| Run the steps | `executePipeline(steps, question, onProgress, signal?)` in `executor.ts` |
| Rows to map features | `transform*ToFeatures(rows)` in `resultTransformer.ts` |
| The question as a sentence | `generateQuestion(question, totals?)` in `questionGenerator.ts` |
| Result-cache key | `cacheKey(question)` in `cacheKey.ts` |
| A result as stored in the cache | `toWire` / `fromWire` in `wire.ts` |
| Warning for questions that reliably fail | `assessQueryBreadth(question)` in `queryBreadth.ts` |
| One raw SPARQL request | `executeSparql(endpoint, query, options?)` in `sparqlClient.ts` |
| SPARQL builders, dropdown discovery queries | `templates/` |
| The question, row and feature types | `types/` |
| Endpoints, prefixes, regions, substances, prebuilt questions | `constants/` |

## Calling it from Node

This is what `scripts/warm-cache.mts` and `scripts/health-check.mts` do:

```ts
import { PREBUILT_QUERIES } from '../engine/constants/prebuiltQueries';
import { planPipeline } from '../engine/planner';
import { executePipeline } from '../engine/executor';
import { generateQuestion } from '../engine/questionGenerator';

const { question } = PREBUILT_QUERIES[0];
console.log(generateQuestion(question));
const result = await executePipeline(planPipeline(question), question, (p) =>
  console.log(p.description, p.status),
);
```

Run a file like that with `npx tsx <file>.mts`.

## Tests

```bash
npm run test:engine   # only engine/tests/, no jsdom
```

- `queryGeneration.test.ts` and `questionText.test.ts` compare the SPARQL and
  the question text for every prebuilt, representative and critical question
  against `tests/__snapshots__/`. Re-record with `npx vitest run -u` and review
  the diff.
- The test questions live in `tests/questions/`, not generated by loops.
