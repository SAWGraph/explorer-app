# Testing

- Tests are Vitest files next to the code they test, flat: `engine/tests/`
  (`engine/tests/queryGeneration.test.ts`) and `ui/tests/`, run by `npm test`.
- No self-check scripts. A check that asserts something is a test. Scripts
  (`engine/scripts/`, `ui/scripts/`, `scripts/ops/`) are for tools that are
  not tests: measurement, asset generation, cache warming.
- Golden-file test inputs are data in `engine/tests/questions/`, not generated by loops:
  - prebuilt questions come from `src/constants/prebuiltQueries.ts`
  - `representative.ts` covers each code path once. Questions that differ only
    by region code add nothing.
  - `critical.ts` holds past breakages, each with a `source` pointing at its
    `docs/DEBUGGING.md` entry.
- Rule tests that must hold for every question shape (`traceDirection`,
  `stepLabels`, `flowlineScope`, `queryJoins`) loop over the full shape space on
  purpose, and assert the loop count so a loop that runs zero times fails.
- Every bug fix leaves a test that fails without the fix. If a map is the only
  way to see the bug, that is the case that most needs a test.
- Tests are offline. Anything that hits a live endpoint belongs in
  `query-matrix` or `health-check`, not `npm test`.
- No coverage targets, no E2E framework. Test the rule that is silent when
  wrong (wrong answer, mislabelled step, colliding cache key).
