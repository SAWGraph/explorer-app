# Changelog, Week 47, 2026 (Nov 16 to Nov 22)

---

1. **Fixed: Most Facilities Were Never Shown, and a County Let In Facilities From the Next One** (2026-11-16)

    **Component**: `engine/entities/facilities.ts`, `anyRegionLinkCheck` in `engine/entities/types.ts`, `buildFacilitiesByIri` in `engine/templates/hydrate.ts`, `ui/components/Map/`

    **Symptom**: Issue #145. With no industry filter, "facilities in Cumberland County" found 603 facilities; the graph has 2,203 there. About three of every four facilities have no NAICS industry code and never reached the map. Separately, a county on a facilities side let in facilities from the next county, because only the S2 cell was checked.

    **Root cause**: The facilities query always required a NAICS industry code, filter or not, and so did the details query. The region pick had no check on the facility itself, the leak #96 fixed for wells and #144 for aquifers.

    **Change**: With no industry filter, a facilities side finds every facility with a location, coded or not (Cumberland 2,166, Cook 40,299). A facility with no recognised code shows "Unspecified or Unknown" as its industry in the popup, the hover tooltip and the list of facilities on a shared point. With any industry picked, including Select all, only facilities with a matching code are found, and Select all now reads "facilities with an industry code". A region now also requires the facility's own link to that county or state (Cook 41,150 to 40,299 before the industry change).

    **Unchanged**: questions with an industry filter send the same queries apart from the region check. Marker colours are the same. The Industry dropdown has no "Unspecified or Unknown" option.

    **Cost**: the dashboard questions hold their times. The Cumberland upstream PFHpA question now shows 558 facilities where it showed 140. Illinois facilities near Illinois wells with no industry filter now fails at the wells details step; tracked in #160.

    **Files touched**: `engine/entities/facilities.ts`, `engine/entities/types.ts`, `engine/templates/hydrate.ts`, `engine/cacheKey.ts` (`DATA_VERSION` 2026-11b), `ui/components/Map/facilityIndustry.ts` (new), `ui/components/Map/MapPopup.tsx`, `ui/components/Map/FacilityLayer.tsx`, `ui/components/Map/StackedPopup.tsx`, `docs/DEBUGGING.md`, `docs/QUERY-SWEEP.md` (Part 12), `docs/SCHEMA.md`, `docs/wiki/Dropdowns Industry.md`

    **Prevention**: `engine/tests/facilityRegion.test.ts` checks the region check on every facilities side with a region and none without, the collapsed side, the no-filter bind and the optional industry in details (with `LIVE_SPARQL=1`, the Cumberland and Cook counts); `ui/tests/facilityPopup.test.tsx` and `ui/tests/stackedPopup.test.tsx` check "Unspecified or Unknown"; `engine/tests/questions/critical.ts` adds facilities in Cook near Cook wells with no filter.

2. **Changed: Question Text and Step Labels Use the Type Menu's Names** (2026-11-17)

    **Component**: `label` on the samples, aquifers and streams modules in `engine/entities/`

    **Change**: Issue #164, a follow-up from #70. The question sentence, the pipeline step labels and the count and empty-result messages now say "sample results", "ground water aquifers" and "streams and flowlines", matching the Type menu.     **Follow-up**: cached dashboard results still list their queries under the old step names until `npm run warm-cache` runs after merge.

    **Files touched**: `engine/entities/samples.ts`, `engine/entities/aquifers.ts`, `engine/entities/streams.ts`

    **Prevention**: `engine/tests/blockWording.test.ts` checks the aquifer and streams wording; `engine/tests/stepLabels.test.ts` checks the sample step labels, and its raw-type-name check now allows labels that contain their type name; `engine/tests/__snapshots__/question-text.txt` re-recorded.

3. **Added: Counts Next to Every Filter Dropdown Option** (2026-11-17)

    **Component**: `buildOptionCountQuery` in `engine/templates/fusedQueries.ts`, `options` on the entity modules in `engine/entities/`, `useOptionCounts` in `ui/hooks/useDiscoveryQueries.ts`

    **Change**: Issue #165, a follow-up from #70. Industry, Feature Type, Aquifer Type and Well classification now show how many entities each option would find: in the selected state or counties, or nationwide with none. Industry used to show counts only once a state was picked, Well classification only for the whole of Illinois or Maine, and Feature Type and Aquifer Type none. Feature Type parents show the sum of their children; Aquifer Type sums the raw values each option covers.

    **How**: each count is the run's own count step with the filter left open and grouped by option, so it checks the region exactly as the run does. Hancock County wells: 7,296, where a count by subdivision link alone gave 11,644. Live queries on `federation`, cached for the session, nothing stored. A failed count leaves the dropdown working, with no numbers.

    **Cost**: measured live on 2026-11-17, 1.8s or less for every type, nationwide and for Maine, Hancock and Illinois, except Illinois aquifers cold (30.1s, 0.46s on a rerun; the run's own count step for that block took 25.8s), where the first open may show no numbers.

    **Unchanged**: the SPARQL every question sends (`query-shapes.txt` did not move). Substance and Material counts.

    **Files touched**: `engine/templates/fusedQueries.ts`, `engine/templates/regions.ts` (`buildIndustryCountsQuery` removed), `engine/templates/wells.ts`, `engine/entities/*.ts`, `engine/optionCounts.ts` (new), `ui/hooks/useDiscoveryQueries.ts`, `ui/components/QueryEditor/` (Facility, SurfaceWater, Aquifer and Well filters, `EntityBlock.tsx`, `FlatSelect/withCount.ts` new), `docs/wiki/Dropdowns Industry Counts.md` (now "Option counts"), `docs/wiki/Dropdowns.md`

    **Prevention**: `engine/tests/optionCounts.test.ts` checks that every counted type's count query carries the same region lines as its count step, for no region, a state, a county and two counties, and how rows become counts; `ui/tests/optionCounts.test.tsx` checks each dropdown shows its counts for the right region, a failed count, and that a region already seen is not fetched again.
