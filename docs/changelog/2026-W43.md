# Changelog, Week 43, 2026 (Oct 19 to Oct 25)

1. **Fixed: Closing the Edit Modal Sent You Back to the Dashboard** (2026-10-20)

    **Component**: `EditModal`, `EditorView`, `AnalysisQuestionBar`, `useQueryPipeline`, the query engine (`executor`, `sparqlClient`), `tours.ts`

    **Symptom**: On a new analysis, closing the Edit modal (X, Esc, outside click or Discard Changes) went to the dashboard instead of closing the modal. After Apply, Customize then X did the same and threw away the results on the map.

    **Root cause**: The modal decided whether to leave the page from the route id `'new'`, which stays `'new'` after Apply. Closing a modal should never have been a navigation. Two related gaps turned up while mapping every flow: after the first save the URL kept pointing at the old analysis, so a refresh reopened the wrong thing, and a running Apply could not be stopped.

    **Fix**: Dismissing the modal now only drops the unapplied edits. The edit tour's Esc exit to the dashboard, which had only worked through that navigate, is now the tour's own `onEscape`. After the first save the URL becomes `/q/saved:<id>` without rerunning or clearing the map, and `basedOnQueryId` only records prebuilt ids. Dismissing mid-run cancels the run: an AbortSignal reaches every SPARQL request, the modal stays open with the edits, and the map keeps the previous result.

    **Files touched**: `src/components/QueryEditor/EditModal.tsx`, `src/components/Layout/EditorView.tsx`, `src/components/Layout/AnalysisQuestionBar.tsx`, `src/hooks/useQueryPipeline.ts`, `src/store/queryStore.ts`, `src/engine/executor.ts`, `src/engine/sparqlClient.ts`, `src/api/resultCacheClient.ts`, `src/tours/tours.ts`, `tests/editModalFlows.test.tsx` (new), `package.json`

    **Prevention**: `tests/editModalFlows.test.tsx` renders the real routes in jsdom and tests every agreed flow, one test per row, for each of the four ways to dismiss. It has to use the plain `MemoryRouter`: a data router's `navigate()` fails silently under jsdom, which made the first version of these tests pass with the bug still in place.

2. **Map Layers and Basemaps Open on Click, and Start Open** (2026-10-20)

    **Component**: `LayerPanel`, `BasemapSelector`

    **Symptom**: Both map panels opened only while the pointer hovered over them and showed a bare icon with no label, so they were hard to find and closed as soon as the pointer drifted off.

    **Root cause**: Opening was pure CSS (`:hover` on `.custom-layer-panel` and `.basemap-selector` in `App.css`), so there was no open state to keep.

    **Fix**: Each panel is a native `<details open>` with a `<summary>` header that shows the icon and a label, "Map Layers" or "Basemaps". Both start open and only the header toggles them, so ticking a layer or picking a basemap inside cannot close the panel. Keyboard toggling comes with `<summary>`. The hover rules are removed. On tablets, phones and short windows, matching `(max-width: 1024px), (max-height: 600px)`, both start closed instead, because open they cover most of the map. `ResultsMap` checks this once when the map loads, so resizing or rotating never overrides the user's choice.

    **Files touched**: `src/components/Map/LayerPanel.tsx`, `src/components/Map/BasemapSelector.tsx`, `src/components/Map/ResultsMap.tsx`, `src/App.css`

3. **Fixed: Water Bodies Drawn Once per Map Cell, Old Lakes Left on the Map** (2026-10-21)

    **Component**: water body detail query (`buildWaterBodiesByIri`), `transformWaterBodiesToFeatures`, `WaterBodyLayer`

    **Symptom**: Reported by David. Re-running a question from Customize left lakes from earlier runs on the map: after seven Hancock County questions, the seventh (the same question as the first) showed 98 water bodies that were not in its answer. The legend said "Surface Water Bodies (1272)" for 234 water bodies, large lakes looked solid while small ponds looked pale, and one question shape (facilities downstream of water bodies) needed 517 MB of polygon text, past the browser's 512 MB limit, so its water bodies could not load.

    **Root cause**: The water body detail query returned `?s2cell`, which nothing reads. A water body touches many S2 cells, so it came back once per cell, each copy repeating the full polygon (Graham Lake 90 times). The transformer kept every copy, so the layer rendered many children with the same React key, and React left some old ones mounted between runs.

    **Fix**: The query still requires a water body to sit in a cell but no longer returns the cell, so each water body is one row (Hancock: 1272 rows to 234, 19.2 MB to 0.8 MB). The transformer also keeps one feature per water body, which covers results already stored in the cache. `@testing-library/dom` is now a direct dev dependency, since `npm install --legacy-peer-deps` skipped it and the jsdom render tests could not run after a fresh install.

    **Files touched**: `src/engine/templates/hydrate.ts`, `src/engine/resultTransformer.ts`, `tests/waterBodyLayer.test.tsx` (new), `tests/__snapshots__/query-shapes.txt`, `docs/DEBUGGING.md`, `package.json`, `package-lock.json`

    **Prevention**: `tests/waterBodyLayer.test.tsx` renders the real layer, runs a wider answer then a narrower one, and checks that only the narrower answer is on the map. Without the fix it fails with 17 polygons from 5 water bodies left where 2 are expected.

4. **Fixed: Wells Offered for States Without Well Data** (2026-10-23)

    **Component**: `EntityTypeSelector`, `RegionSelector`, `WellFilters`, `EntityBlock`, `FlatSelect`

    **Symptom**: Issue #71. Well data only exists for Illinois and Maine, but Wells could be picked as the type with Vermont as the state, and with Wells picked the State dropdown still offered Alabama, Arizona and the other covered states. Switching the state from Maine to Illinois kept Maine well classifications: they were hidden in the dropdown but still went into the query and the question text.

    **Root cause**: The Type and State dropdowns did not know about each other. State greying came only from `AVAILABLE_STATE_FIPS`, which is the same for every type, and a state change kept every filter.

    **Fix**: With a state other than Illinois or Maine, Wells is greyed out in the Type dropdown. With Wells as the type, every other state is greyed out. Hovering a greyed option shows why, through a new optional `title` on `FlatSelect` options. A state change drops well classifications from the other state. Once Illinois or Maine is chosen, the classification headers drop the state name ("Purpose", "Type", "Use"). With no state chosen, Wells still covers both states and the headers keep the state name.

    **Files touched**: `src/components/QueryEditor/EntityTypeSelector.tsx`, `src/components/QueryEditor/RegionSelector.tsx`, `src/components/QueryEditor/WellFilters.tsx`, `src/components/QueryEditor/EntityBlock.tsx`, `src/components/QueryEditor/FlatSelect/FlatSelect.tsx`, `src/constants/wellClassifications.ts`, `tests/wellStateGating.test.tsx` (new)

    **Prevention**: `tests/wellStateGating.test.tsx` renders the real block in jsdom and checks both greying rules, their hover text, and that a switch from Maine to Illinois keeps only the Illinois picks.
