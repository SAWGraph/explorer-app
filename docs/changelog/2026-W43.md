# Changelog, Week 43, 2026 (Oct 19 to Oct 25)

---

1. **Fixed: Closing the Edit Modal Sent You Back to the Dashboard** (2026-10-20)

    **Component**: `EditModal`, `EditorView`, `AnalysisQuestionBar`, `useQueryPipeline`, the query engine (`executor`, `sparqlClient`), `tours.ts`

    **Symptom**: On a new analysis, closing the Edit modal (X, Esc, outside click or Discard Changes) went to the dashboard instead of closing the modal. After Apply, Customize then X did the same and threw away the results on the map.

    **Root cause**: The modal decided whether to leave the page from the route id `'new'`, which stays `'new'` after Apply. Closing a modal should never have been a navigation. Two related gaps turned up while mapping every flow: after the first save the URL kept pointing at the old analysis, so a refresh reopened the wrong thing, and a running Apply could not be stopped.

    **Fix**: Dismissing the modal now only drops the unapplied edits. The edit tour's Esc exit to the dashboard, which had only worked through that navigate, is now the tour's own `onEscape`. After the first save the URL becomes `/q/saved:<id>` without rerunning or clearing the map, and `basedOnQueryId` only records prebuilt ids. Dismissing mid-run cancels the run: an AbortSignal reaches every SPARQL request, the modal stays open with the edits, and the map keeps the previous result.

    **Files touched**: `src/components/QueryEditor/EditModal.tsx`, `src/components/Layout/EditorView.tsx`, `src/components/Layout/AnalysisQuestionBar.tsx`, `src/hooks/useQueryPipeline.ts`, `src/store/queryStore.ts`, `src/engine/executor.ts`, `src/engine/sparqlClient.ts`, `src/api/resultCacheClient.ts`, `src/tours/tours.ts`, `tests/editModalFlows.test.tsx` (new), `package.json`

    **Prevention**: `tests/editModalFlows.test.tsx` renders the real routes in jsdom and tests every agreed flow, one test per row, for each of the four ways to dismiss. It has to use the plain `MemoryRouter`: a data router's `navigate()` fails silently under jsdom, which made the first version of these tests pass with the bug still in place.
