1. **Fixed: Sample Popup Table Spilled Out of the Box on First Open** (2026-10-26)

    **Component**: `SamplePopup` in `MapPopup`

    **Symptom**: Issue #84. The first time a sample point's popup opened, the box stayed as narrow as the "Loading measurements…" placeholder and the substance table ran past its right edge. Opening the same point again looked right.

    **Root cause**: Leaflet measures a popup's size and anchor once, when it opens. react-leaflet calls `update()` on `popupopen` and never again. The observation rows arrive later from `useSampleDetails`, so the box kept the placeholder's size. The second open looked right only because React Query already had the rows.

    **Fix**: `SamplePopup` calls `update()` on the open popup when its rows arrive. This was first written for the demo branch (PR #59, commit `8c34f8e`) and never reached `development`. Measured on Penobscot and Knox samples: without the fix the table overflowed the box by 67 px and 117 px; with it the box grew to 547 px and the table fit.

    **Files touched**: `src/components/Map/MapPopup.tsx`, `tests/samplePopupSize.test.tsx` (new)

    **Prevention**: `tests/samplePopupSize.test.tsx` opens a sample popup, resolves its rows, and checks that Leaflet re-measured it. Without the fix it fails with `expected "update" to be called at least once`.

2. **Grouped Type Menu, and One Surface Water Entry** (2026-10-26)

    **Component**: `EntityTypeSelector`, `EntityBlock`, `SurfaceWaterFilters` (new), `HierarchicalSelect`

    **Symptom**: The Type menu was a flat list of six entries, and surface water was split across two of them, "Surface Water Bodies" and "Streams / Flowlines". Each had its own filter behind "+ Add Filters", so finding streams meant knowing to pick a different Type (#70).

    **Change**: The Type menu is grouped into Samples (Sample Results), Features (Facilities, Surface Water, Ground Water (Aquifers), Wells), Environmental Variables and Model Output, the last two holding a disabled "Coming soon" row. Surface Water opens a Feature Type tree right away, with Surface Water Bodies and Streams and Flowlines as tickable parents. Only one parent holds ticks at a time, and it sets the block's type, `waterBodies` or `streams`. The default is Surface Water Bodies. Unticking a parent leaves the tree empty so a single child can be picked next; applied empty, the block runs as Surface Water Bodies and shows that chip. A whole parent, or every child of it ticked, is stored as no filter, so the SPARQL and the cache key match an unfiltered block. NHDPlus FTYPEs that are rare or absent in the source files (Inundation Area, Estuary, Ice Mass, Playa, Drainageway, Underground Conduit) are left out, as agreed on #70 with the NHDPlus maintainer; the one Inundation Area record in the graph is still included when the whole Surface Water Bodies parent is ticked. The Type menu has a minimum width so the longer names do not wrap.

    **Unchanged**: no file under `src/engine/` changed. Question text, step labels, map layers and saved questions are as before; a saved `streams` question loads as Surface Water with Streams and Flowlines ticked.

    **Files touched**: `src/components/QueryEditor/EntityTypeSelector.tsx`, `src/components/QueryEditor/EntityBlock.tsx`, `src/components/QueryEditor/SurfaceWaterFilters.tsx` (new), `src/components/QueryEditor/WaterBodyFilters.tsx` and `StreamFilters.tsx` (removed), `src/components/QueryEditor/HierarchicalSelect/HierarchicalSelect.tsx`, `TreeNode.tsx`, `src/constants/featureTypes.ts`, `src/App.css`, `docs/wiki/Dropdowns.md`, `tests/surfaceWater.test.ts` (new)

    **Prevention**: `tests/surfaceWater.test.ts` covers the mapping between Feature Type ticks and the stored `{ type, ftypes }`: switching parents, a whole parent stored as no filter, and each saved block shape round-tripping. The unchanged `question-text.txt` and `query-shapes.txt` snapshots show the question text and SPARQL did not move.

3. **Fixed: Stream and County Popups Opened Under the Map Data** (2026-10-28)

    **Component**: `ResultsMap`, `RegionBoundaryLayer`, `StreamLayer`, `AquiferBoundaryLayer`

    **Symptom**: Issue #86. A county popup sat behind the county outlines and the facility squares, and a stream popup behind the streams and the facilities. The county popup was on top at 0 of 15 points inside its box, so its close button could not be clicked. After aquifers had been turned on once, stream and county lines could not be clicked or hovered until a reload.

    **Root cause**: The county and stream layers were wrapped in react-leaflet `<Pane>` elements, and a `<Pane>` hands its pane to every child, popups included. So their popups opened in `regionPane` (z 350) and `streamsPane` (z 380), under the data. Tooltips had been fixed one by one in May with `pane="tooltipPane"`; the popups added three days later were not. The aquifer canvas renderer had no pane, so it sat in `overlayPane` (z 400) above streams and counties.

    **Fix**: Each layer names its pane with a `pane` prop, and `ResultsMap` creates the panes with childless `<Pane />` elements. The aquifer renderer draws in `aquiferPane`. The eight `pane="tooltipPane"` props and the `.leaflet-tooltip` z-index rule, workarounds for the same trap, are gone. Measured on localhost: both popups on top at 15 of 15 points, and streams clickable at 142 of 142 points with aquifers on and off. Every popup on four more prebuilt questions (samples, wells, water bodies, Indiana streams) also opened on top.

    **Files touched**: `src/components/Map/ResultsMap.tsx`, `src/components/Map/RegionBoundaryLayer.tsx`, `src/components/Map/StreamLayer.tsx`, `src/components/Map/AquiferBoundaryLayer.tsx`, `SampleLayer.tsx`, `FacilityLayer.tsx`, `WaterBodyLayer.tsx`, `WellLayer.tsx`, `src/App.css`, `eslint.config.js`, `tests/mapPanes.test.tsx` (new), `docs/DEBUGGING.md`, `docs/CONVENTIONS.md`

    **Prevention**: `tests/mapPanes.test.tsx` checks the pane of every shape, popup and tooltip, and of the aquifer canvas. Without the fix it fails on the county and stream popups and the aquifer canvas. An ESLint rule rejects layers nested inside `<Pane>`.

4. **Engine and UI Split into Separate Top-Level Folders** (2026-10-29)

    **Component**: repo layout; `engine/`, `ui/`

    **Change**: `src/` is gone. The planner, executor, SPARQL templates, and the types, constants and question text they use now live in `engine/`, with their tests in `engine/tests/`. The React app lives in `ui/`, with its jsdom tests in `ui/tests/`. `server/` is unchanged. Each folder has a README. The goal is that the UI can be rebuilt without touching the engine.

    **Guard**: `engine/tests/headless.test.ts` fails if any engine file imports a package or anything outside `engine/`, or uses `window`, `document`, `localStorage`, `sessionStorage`, `navigator` or `import.meta.env`. The engine's own tests are held to the same import rule, with only `vitest` and Node builtins added, because merging `development` into this branch once put a UI test (`mapPanes.test.tsx`) in `engine/tests/`. It caught every leak injected while writing it: `react`, `leaflet`, an import from `ui/`, a multi-line import from `ui/`, `window`, `import.meta.env`, `localStorage`, `node:fs` in engine code, and that UI test placed in `engine/tests/`. `npm run test:engine` and `npm run test:ui` run one side each; `npm test` still runs both.

    **Unchanged**: behaviour. Apart from import paths, the only code change is that map features carry coordinates as a plain `[lat, lon]` pair instead of Leaflet's `LatLngExpression` type, which was the engine's one import from a UI library; the JavaScript that runs is the same. `src/utils/naicsResolver.ts`, which nothing imported, is deleted. `index.html`, `vite.config.ts`, `public/` and `package.json` stay at the root, so Railway builds and serves the frontend exactly as before.

    **Files touched**: every file under `src/` and `tests/` (moved), `index.html`, `tsconfig.app.json`, `package.json`, `scripts/*.mts` (import paths), `scripts/precompute_aquifers.py`, `engine/README.md` and `ui/README.md` (new), `engine/tests/headless.test.ts` (new), `ui/tests/mapPanes.test.tsx` (moved from `tests/` when `development` was merged in), `docs/ARCHITECTURE.md` and the path references in the living docs
